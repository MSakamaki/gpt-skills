# METHOD: CONSIDER_OPPOSITE

## Role

EXECUTABLE_METHOD

## Purpose

回答案の結論と反対の結論を、否定するためではなく **成立させるために** 構成する。その過程で、回答案が拾っていない情報と、結論を支えている解釈の偏りを露出させる。

## Covers

- F02 CONFIRMATION — 現在の結論を支持する情報へ偏る
- F03 ALTERNATIVE — 代替案・代替解釈の不足
- F07 CONSENSUS — 初期回答への同調

## Applicable When

次のいずれかを満たす。

- 回答案が明確な結論・推奨・判定を含む
- 回答案が、対立しうる立場の一方だけを展開している
- 同じ入力情報から別の結論を導きうる

## Do Not Use When

- 回答案に反転させられる結論がない (列挙・整理のみの回答)
- 観測事実の原因を特定する問題であり、対立仮説を証拠で識別できる (この場合は COMPETING_HYPOTHESES)
- 結論が回答仕様で与件として固定されている
- 反対の立場が事実に反することが既に確定している (誤情報の擁護になるため)

## Inputs

- 固定済み `V(i-1)`
- 回答案の結論と、それを支える根拠
- 回答仕様の評価基準 (項目 7)

## Procedure

1. 回答案の結論を 1 文で書く。条件付きの結論なら、条件も含めて書く。
2. その否定形を書く。「そうとは言えない」ではなく、反対側の立場を積極的な主張として書く。
3. 反対の結論を **支持する立場に立って** 構成する。
   - 同じ入力情報のうち、反対側を支持する部分を挙げる
   - 回答案が採用した解釈以外の解釈を挙げる
   - 反対側が成立するために必要な条件を挙げ、それが満たされているかを確認する
4. 反対の結論が成立するために不足しているものを特定する。
5. 元の結論と反対の結論を、回答仕様の評価基準で比較する。どちらが強いかではなく、**判断を分けている要因**を特定する。
6. 次のいずれかへ着地させる。
   - 元の結論を維持する — 反対側が成立しない理由を根拠付きで記録する
   - 条件を付ける — どの条件下で結論が反転するかを回答案へ追加する
   - 結論を変える — 反対側のほうが根拠が強い場合
7. 回答案が、反対側の主要な論点に触れていない場合を指摘する。

### Research-backed

現在の信念と食い違う可能性を意図的に考えさせることで、biased assimilation や biased hypothesis testing への補正を図るという considering the opposite の方略。

### Skill-specific adaptation

手順 3〜7 の構成規則と着地の 3 分類は本 Skill の運用規則である。原典 PDF は再配布条件を満たさず未取得のため、原典の実験条件・効果量に基づく主張は行わない。

## Output

- Original conclusion — 元の結論
- Opposite conclusion — 反対の結論
- Support for opposite — 反対側を支持する情報・解釈・条件
- Missing for opposite — 反対側が成立するために不足しているもの
- Deciding factor — 判断を分けている要因
- Resolution — 維持 / 条件付与 / 変更 と、その根拠
- Gap — 回答案が触れていない論点

## False Positive Guard

- 反対の結論が成立しないことを確認できた場合、それを指摘にしない。確認した事実として記録し、回答案を弱めない。
- 「別の見方もある」という一般論を指摘にしない。反対側を具体的に構成できたものだけを扱う。
- 反対側を構成できたことを、元の結論が誤っている証拠として扱わない。
- 断定を避けるだけの書き換えを修正として採用しない (F16)。

## Stop Condition

反対の結論を構成し、成立条件と不足を特定し、着地を決めた時点で終了する。同じ結論に対して繰り返さない。
